КАК БЕЗОПАСНО ДОБАВИТЬ ТРЕК НА САЙТ
=====================================

ВАЖНО
------
Исходные материалы, таблица соответствий, скриншоты и student_mapping.txt
должны храниться вне репозитория сайта. Не добавляйте в публичные файлы ФИО,
локальные пути или другие персональные данные.


1. ПОДГОТОВЬТЕ ПУБЛИЧНЫЙ MP3
----------------------------
Создайте копию исходного файла. Удалите из копии ID3 и другие метаданные,
которые могут содержать персональные данные. Исходник не изменяйте.

Имя публичного файла формируйте из никнейма: только строчные латинские буквы,
цифры, дефисы и точки. Пример: tracks/example-name.mp3.


2. ПОДГОТОВЬТЕ ОБЛОЖКУ
----------------------
Используйте безопасное латинское имя. Удалите EXIF/XMP и текстовые поля.
Рекомендуемый размер — до 1024×1024: карточке не требуется исходник 2048×2048.
Не меняйте визуальное содержание изображения.


3. ДОБАВЬТЕ КАРТОЧКУ
--------------------
Вручную добавьте объект в collection.json, не меняя порядок существующих
карточек. Допустимые публичные данные ученика:

- student: точный никнейм из приватной таблицы;
- title: «Код ДНК: <числовой код>»;
- module: внутреннее значение, которое не выводится в карточке;
- file: относительный путь к безопасной публичной копии MP3;
- duration: длительность;
- cover: относительный путь к публичной обложке.

ФИО и связь ФИО ↔ никнейм фиксируйте только во внешнем student_mapping.txt.


4. ПРОВЕРЬТЕ ДЛИТЕЛЬНОСТИ И ПУТИ
--------------------------------
Выполните:

npm run update-tracks

Команда сохраняет никнеймы, коды, порядок и обложки. Она обновляет только
длительности и останавливается, если путь небезопасен, файл отсутствует или в
папке tracks обнаружен MP3 без карточки.


5. ПРОВЕРЬТЕ ПРОЕКТ
-------------------
Выполните:

npm run build

Проверка подтверждает наличие ресурсов, безопасные относительные пути, формат
кодов ДНК и отсутствие ID3 в публичных MP3. После этого проверьте карточку и
воспроизведение локально. Не публикуйте сайт до завершения проверки.
